# BDSS Annual Datathon — Lloyds Banking Group
### Credit Card Fraud Detection: Model Performance vs Environmental Footprint

---

## 📋 Overview

This project was built for the BDSS × Lloyds Banking Group Datathon. The challenge is to build multiple machine learning models for credit card fraud detection and compare their **predictive performance** against their **environmental footprint (CO₂e)**.

The core question we're answering:
> *Is a more complex model worth the carbon cost compared to a simpler one?*

## 🚀 Getting Started

### 1. Clone the repo
```bash
git clone <repo-url>
cd bdss-datathon
```

### 2. Install dependencies
```bash
pip install -r requirements.txt
```

### 3. Download the dataset
Download `creditcard.csv` from Kaggle:
https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud

Place it at `data/creditcard.csv`.

### 4. Run the shared baseline
> ⚠️ **One person does this and commits the outputs. Everyone else skips this step and pulls.**

Open `shared_baseline.ipynb` and run all cells. This will generate:
- `splits/data_splits.pkl` — the shared train/test splits
- `models/baseline_lr.pkl` — the trained baseline model
- `results/summary_baseline.json` — baseline metrics
- `results/eda_*.png` — EDA plots

Commit and push these outputs so everyone else can load them.

### 5. Run your own model notebook
Each team member runs their own notebook (e.g. `model_E_finbert.ipynb`).
Each notebook:
- Loads `splits/data_splits.pkl`
- Trains their assigned model
- Saves `results/summary_<X>_<model>.json`

Push your summary JSON when done.

### 6. Build the leaderboard
Once all summary JSONs are pushed, run `comparison.ipynb` to generate the final leaderboard and performance vs carbon plots.

## 📊 Metrics

| Metric | Role |
|--------|------|
| AUPRC | **Primary** — handles class imbalance correctly |
| AUC-ROC | Secondary — standard comparison metric |
| F1 Score | Summary of precision & recall |
| CO₂e (kg) | Environmental cost of training + inference |
| Efficiency Score | `Normalised AUPRC / Normalised CO₂e` — leaderboard formula |

> The dataset is highly imbalanced (0.172% fraud). Accuracy is **not** a useful metric here.

## 🌱 Carbon Estimation

All notebooks use consistent assumptions for fair comparison:

| Assumption | Value |
|------------|-------|
| CPU power draw | 0.045 kW |
| GPU power draw | 0.150 kW |
| UK grid carbon intensity | 0.233 kg CO₂/kWh |

Formula:
```
kWh     = (runtime_seconds / 3600) × power_kw
CO₂e_kg = kWh × carbon_intensity
```

## 📦 Dataset

**Credit Card Fraud Detection** — Kaggle / ULB Machine Learning Group

- 284,807 transactions over 2 days (September 2013, European cardholders)
- 492 frauds (0.172% of total)
- Features V1–V28: PCA-transformed (anonymised)
- Features Time, Amount: raw (scaled in preprocessing)
- Target: `Class` (1 = fraud, 0 = genuine)

> Dataset is not included in this repo due to size. Download from Kaggle (link above).

## 📌 Important Rules

- **Do not re-run `shared_baseline.ipynb`** after splits are committed — it will change the data and break comparability
- **Do not commit** `data/creditcard.csv` or the `models/` folder
- **Do commit** your `results/summary_<X>_<model>.json` and any plots you generate
- Keep `POWER_KW`, `CARBON_INTENSITY`, and `random_state=42` consistent across all notebooks
